How to talk about it (the decisions, not the pixels)

One screenFits one iPad screen with no scroll, landscape and portrait, from 9.7-inch to 12.9-inch. Fixed header, floating status card, fixed action dock. A worker's eye learns where things live.
HMI, not webNo small text (body 14px+, labels 13px+), no text selection, no double-tap zoom, every tappable thing is a 48–72pt glove button. "Send tech" is a button that opens a hold-to-confirm sheet, never a link.
Status firstTop lockup = title bar + machine-at-a-glance line (every component, one dot, one word). Then the status card: all ingredients grouped by a taxonomy (proteins, bases, vegetables, sauces, dairy), mains bigger than toppings, each with a photo, a percent and a refill-by forecast from the Thursday lunch curve.
Actions dockHooked to the bottom edge, edge to edge, dark. Left: what and where, plus two secondary buttons. Middle: minutes-until-late is the hero, the other two numbers under it. Right: one verb-specific action ("TAP TO START REROUTE"). The worker never has to decide what the button does.
No redRed fails for color-blind workers under kitchen light. Needs-you-now is the hot yellow-green of the action button; on the light panel the box itself goes dark with yellow numbers. Low is amber. Fine is green. The alert dot is hot orange so it never competes with the button.
Progress bar is the messageThe level fill is the primary signal; the number confirms it. Numbers that tick use tabular figures so nothing jitters. State changes ease; nothing snaps.
RecipeEach machine is a company; each order is a series of bowls for one customer. À la carte within a range, or a recipe: "SF-0912 · Salesforce · 50 bowls · Salesforce Tower · Wed 12:30". The recipe row shows progress, minutes to due, and the hoppers it depends on with problems first; those hoppers carry an SF tag. That is the bridge between the order system and the machine.
Scripted shiftIt's a scene, not a mock: quinoa under-dispenses, the worker reroutes, then a quick fix, a release, a door interlock, a cleaning cycle, then chicken runs low. Manager numbers drift live.
ProcessBuilt in one session from the job description: the worker asked for calm colors, one key fact per box, mains bigger than toppings, and a dock. Every revision was verified on iPad sizes in the browser before it shipped. The rules are written down (PANEL-DESIGN.md) so the next designer keeps them.

Design cues · say them like you mean them

The rules the prototype runs on, each with the why. These are the sentences that make you sound like the person who already owns the panel.

State is the color; the number is the detail.
A worker across the room reads color in 100 ms and numbers in a second. Color answers "do I move"; the number answers "how much".
Every state is a color first. If you can't tell the state from six feet, the panel failed.
No red.
About 8% of men can't separate red from green, and kitchen light is warm. The alert color is the action color, so the eye lands on the fix.
I took red out. Needs-you-now is the hot yellow-green of the button that fixes it.
The progress bar is the message.
A fill level is pre-attentive. The worker doesn't read 16%; they see a short bar.
The bar is the message. The percent and the refill-by time confirm it.
Fixed header, floating status, fixed dock.
Three zones a hand learns. The machine at the top, the food in the middle, the next action at the bottom, always in the same place.
Nothing moves. The dock is hooked to the bottom edge so the thumb finds the button without looking.
Glove-first.
48pt minimum, 72pt for the one action, hold-to-confirm for anything with a cost. No text links, no double-tap zoom, no text selection.
This is an HMI, not a web page. Everything tappable is a button a gloved hand can't miss.
Mains bigger than toppings.
Proteins and bases stop the line; cilantro doesn't. Size is priority.
Chicken and rice can be read from across the kitchen. The toppings are scannable up close.
One verb per alert.
A generic OK makes the worker decide. "Tap to start reroute" tells them what will happen.
The button says the verb. Reroute, release, start cleaning. The worker never has to think about what OK does.
Minutes-until-late is the hero.
Time pressure decides the next move; counts explain it.
Of the three numbers, the minutes lead. The other two sit under it.
Recipe = the job.
Each machine is a company; each order is bowls for one customer. À la carte within a range, or a named batch.
The recipe row is the bridge between the order system and the machine. It tags the hoppers it depends on.
One token source, two skins.
Light and dark share every size, radius, spacing and rule; only the color layer changes. The design system is the contract.
Reskin via tokens, never rewrite. Firmware, cloud and UX read the same page.
No small text.
Body 14px, labels 13px, on a wall-mounted iPad. Bigger, bolder, higher contrast, never cute.
I set floors. Nothing on the panel is under 13 points.
Done = verified on the device.
Every change was measured at four iPad sizes before it shipped. A panel that clips is a panel that lies.
I don't ship a screen I haven't seen on the hardware it lives on.

Day one, week one, month one

If she asks "what would you do first", this is the answer. It is the plan the prototype was built to prove.

Day one

  • Stand at a line during a lunch rush. Watch hands, not screens. Count taps and glances.
  • Get the machine's real state list from firmware and the real alert list from cloud. Those become the color map.
  • Put the current panel on the wall next to my prototype and ask the worker which one they'd keep.
  • Meet the mechanical, electronics, firmware and cloud leads. Ask each what the screen gets wrong today.

Week one

  • Publish the token page as the contract: states, colors, sizes, floors. Firmware, cloud and UX build against it.
  • Ship worker panel v1 on the real data: one screen, three zones, no red, glove-first.
  • Define the taxonomy with the food team and the recipe model with ops. Names on the boxes are theirs, not mine.
  • Instrument it: time-to-act per alert, taps per task, refills before empty, false alerts.

Month one

  • Manager console from the same tokens: who needs me, who's off plan, throughput.
